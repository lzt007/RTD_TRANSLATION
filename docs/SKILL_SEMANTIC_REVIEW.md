覆核日期：2026-11-01。僅提交本報告，未修改 `translations.csv`、模板或既有譯文。

## 範圍與方法

- 逐一對照 `metadata/skill-patterns.json` 的 **228 個日文模板**與 `metadata/skill-pattern-translations.tsv` 的繁中模板，檢查作用對象、發動條件、條件方向、時限、使用次數、加算／倍率、百分比、屬性、無效及重複限制。
- 閱讀 `scripts/translate_skills.py` 的 `PATTERN`、`TERMS`、`normalize()` 和展開邏輯；以相同方式唯讀展開實際 CSV 記錄，檢查變數替換後的句意，而非只比對標籤。
- 現有 CSV 實際匹配 **1,113 條、228 個模板**，1,113 條均存在於 `metadata/handoff-existing-translations.json`。重新展開與 CSV 現譯的差異為 **0 條**。差額已定位：其中 1 條為台服原有 `？？？`（CSV 記錄 67、模板 37）；扣除此條，即為交接的 1,112 條新增技能效果。詳細追溯見下節。
- 下文「CSV 記錄」以表頭為第 1 筆、第一筆資料為第 2 筆計數；原文可能含換行，因此不是文字編輯器的實體行號。模板編號為 JSON 的 **0 起算索引**。

`metadata/locations.json` 將同一來源追溯至 `sources/TextDatabase.json` 的記錄 65、鍵 `RR_UN`，以及 `ACTIVE_SKILL_MASTER.json` 的 `text` 欄位，業務 ID 29171、29172、29173、29174（record_index 385–388）。主表依原文去重，這些來源只形成一條。計數因而為 **1,112 條新增技能譯文＋1 條台服既有問號＝1,113 條模板匹配**。

## 明確語義錯誤：金幣增加量被譯成變為指定值

**模板 126，影響 6 條。**

日文模板：`クエストクリア時のゴールド報酬が@0@@1@@2@@3@なります。@4@(重複可)@5@`

現譯模板：`任務完成時獲得的金幣報酬變為@0@@1@@2@@3@。@4@(可重複)@5@`

實際例（CSV 記錄 3455）：

```text
原文：クエストクリア時のゴールド報酬が[5ef5f7]500[-]多くなります。[5ef5f7](重複可)[-]
現譯：任務完成時獲得的金幣報酬變為[5ef5f7]500[-]大幅。[5ef5f7](可重複)[-]
建議：任務完成時獲得的金幣報酬增加[5ef5f7]500[-]。[5ef5f7](可重複)[-]
```

`500多くなります` 表示「多 500／增加 500」，不是報酬變成 500，也不是抽象的大幅增加。`TERMS['多く']='大幅'` 在此把數量補語錯當程度詞，造成實際句意及文法同時錯誤。六個實例的 `@3@` 都是 `多く`，增加量及記錄如下：

| CSV 記錄 | 增加量 |
|---|---:|
| 3455 | 500 |
| 3457 | 1,000 |
| 3459 | 1,500 |
| 3461 | 2,000 |
| 3463 | 2,500 |
| 3465 | 3,000 |

若之後獲准修正，模板 126 可改成 `任務完成時獲得的金幣報酬增加@0@@1@@2@。@4@(可重複)@5@`。此處不應單獨全域更改 `多く` 的詞典映射，其他語境需另判斷。現行腳本只填空白且保護既有譯文，修改模板後重跑也不會自動改掉這六條既有內容；需由整合者明確處理。

## 應修正的限制措辭：不可疊加被寫成不可再次施放

**13 個模板、53 條**將 `重ねがけ無効` 譯為 `不可重複施放`。原文限制的是重複套用效果的疊加，不能僅憑這句推論技能禁止再次施放。中文目前容易讓玩家誤認為不能重施。

| 模板 | 實例數 |
|---|---:|
| 9 | 6 |
| 17 | 5 |
| 18 | 6 |
| 22 | 6 |
| 48 | 3 |
| 49 | 9 |
| 58 | 4 |
| 59 | 5 |
| 60 | 5 |
| 66 | 1 |
| 70 | 1 |
| 84 | 1 |
| 85 | 1 |

實際例（CSV 記錄 1267，模板 9）：

```text
原文：現戦闘中に受けるダメージを[5ef5f7]僅かに[-]減少させます。（重ねがけ無効）
現譯：本次戰鬥中，受到的傷害[5ef5f7]微幅[-]減少。(不可重複施放)
建議：本次戰鬥中，受到的傷害[5ef5f7]微幅[-]減少。此技能效果不可疊加。
```

同樣措辭亦出現在回復加減傷（記錄 1918、模板 60）及減傷加攻擊力（記錄 2069、模板 84）。建議統一使用 `此技能效果不可疊加。`，不另行承諾重施時會刷新、覆蓋或無效；這些細節原文未說明，也未經執行期驗證。

## 正規化造成的假警報與仍有歧義

- `PATTERN` 會把 `無効／無視／無数` 中的 `無` 當成變數。有些譯文模板沒有保留相應 `@n@`，但「無效／無視／無數」已在固定中文中正確表達；不能據此判為漏譯。
- 模板 60、84 的日文動詞 `減少します／減少し` 會被抽出 `少し`。這不是額外的「小幅」程度詞；中文直接寫「減少」正確，不能因省略該變數而再補「小幅」。模板 71 的 `強力な` 亦已由「愈強」涵蓋。
- 模板 10、163、214、217 的 `に減少／に上昇` 形式不能單憑模板認為「降至／升至」遭譯成增減量。核對實際變數後，相關形式使用 `僅か` 程度詞，現譯微幅下降／上升可成立。
- 模板 41 的復活百分比沒有在日文句內明說以最大生命值為分母，現譯亦未擅加；若需玩法上的完整定義，仍須查遊戲實作，不能僅靠這句判錯。
- `少し／凄く／物凄く／超絶` 等程度級別目前採小幅／大幅度／極大幅／超大幅等對應。文字層面未見級別顛倒；其實際倍率、跨技能是否同倍率，不能由無數值的說明單獨驗證。
- `重複可／重複不可` 沒有在原文逐一說明是多名持有者、同技能還是異技能的疊加規則；本次不替原文補出未提供的規則。上文 53 條明確帶有 `重ねがけ`，故可指出「施放」措辭的問題。
- 模板 37 的 `？？？` 原樣保留，沒有可供翻譯的效果資訊。本次是文本語義覆核，未執行遊戲、未驗證技能運算程式，也未將文本一致性宣稱為玩法已驗證。

結論：需交由整合者決定是否突破「保留既有譯文」約束的具體候選為 **6 條金幣數量錯譯**及 **53 條疊加限制措辭**。兩組互不重疊。其餘模板未發現明確語義錯誤，但以上未明說的玩法細節仍保留歧義。

## 逐條勘誤提案交付

`metadata/legacy-translation-errata.csv` 列出全部 59 條的「源文本、現有譯文、建議譯文、原因」。其中 53 條保留原有前句，僅將 `(不可重複施放)` 替換為 `此技能效果不可疊加。`；6 條金幣報酬改為「增加數量」。全部建議譯文已檢查字庫、NGUI 標籤、string.Format 參數及數字多重集合，均通過。只提供建議，沒有修改主 CSV 或模板；其餘既有譯文亦未變動。
