# 翻译文件与共享消费契约

## CSV 编辑规则

表头必须严格为 `源文本,中文文本`，顺序不变，不能多加 ID、备注或出处列。CSV 使用 UTF-8，可带 BOM；逗号、双引号及真实换行使用标准 CSV 引号转义。多行单元格属于一条记录，不可按物理文本行拆分。用 Excel 导入时将两列均指定为文本，避免公式、数字和日期自动转换；导出后务必运行校验并核对版本差异。

源文本进行精确 Unicode 匹配，不 Trim、不规范化、不改换行、不把全角替换成半角。前后空格及 CR/LF 差异有意义。真实换行与两个字符 `\n` 也不同，原数据是什么就保留什么。JSON 中的转义由导出器处理，不要在 CSV 中提前添加 JSON 反斜杠转义。

中文为空或全部为空白字符表示“暂不替换”，不会写入 JSON；有实际文字的中文保留前后空格。相同源文的相同非空译文可以合并；空译文与非空译文并存采用非空值；不同非空译文冲突时拒绝整个导出。不能靠复制同一原文多行实现不同上下文译文。

保护 `{0}`、`{1,3:N2}` 等 `string.Format` 占位符，编号、出现次数、对齐和格式均须保持，允许调整顺序。`{{`、`}}` 是转义花括号，数量也须保持。未配对或不合法花括号会报错；遇到普通字面花括号需要先人工核实用途，不自行删除或绕过校验。

导出器保护 ASCII 方括号标记，例如颜色 `[d9419a]`、复位 `[-]`、样式与符号名称 `[b]`、`[/b]`：标记内容和出现次数不变，位置可以随译文调整。检查是保守的语法检查，不证明标签嵌套、字体符号和游戏渲染一定正确；非 ASCII 方括号内容（如日文称号）不自动认定为 NGUI 标签。发布前还要人工核实嵌套与实际符号。

## UTF-8 JSON 交付

输出为 UTF-8 无 BOM，根必须是纯 JSON 对象，每个键和值都是字符串：

```json
{
  "源文 {0}": "译文 {0}"
}
```

不含版本包装、ID、来源、CSV 表头或空译文。键为原文，不是 GameText key 或主表业务 ID。初次未填写时输出 `{}`。输出不带重复键。JSON 转义恢复后必须与 CSV 单元格逐字符一致。

导出前全部校验，失败退出码为 1，输出错误记录序号；成功为 0。失败不会覆盖先前已发布文件；因此失败后不得误把旧产物当作本轮新交付。成功后采用同目录临时文件和原子替换，避免半写 JSON。

客户端消费约定：缺失、不可读、损坏、根不是对象或条目不合法时，整份映射回退为空字典；先完整读取校验临时字典，成功后一次发布。空白译文应忽略，冲突重复键应拒绝，键值不能强制转换或 Trim。只有显示原文命中时替换，不能更改业务 getter、协议 ID、玩家输入、密码和玩家名。JSON 不要求本项目的 Python 代码进入客户端。

本契约允许显示层精确查表；动态拼接、格式化后的成品文本不能自动命中格式化前模板。是否支持 GameText 模板入口由客户端实现范围决定。导出器能保护占位符，但不会自动补齐缺失的显示钩子或中文字形。
